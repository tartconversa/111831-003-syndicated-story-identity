# 分析口径

当前项目的观察重点是 story lineage and editorial additions。来源信息、观测记录与分析输出分别保存；报告保留生成时使用的来源标识，便于研究人员回看数据范围。输入观测的数值含义由调用方提供，项目不将报道计数解释为受众态度或传播因果。

## 转载与独立增补的区分

一条通讯稿被多家网站转载时，计数必须同时回答两个问题，二者使用不同口径、不合并成单一“报道数”：

| 口径 | 含义 | 纯转载是否计入 | 有本地增补的转载是否计入 |
| --- | --- | --- | --- |
| `reached_sources` | 内容实际传到了哪些来源（传播范围） | 计入 | 计入 |
| `independent_reporting_sources` | 哪些来源提供了新的报道信息 | 不计入 | 计入 |
| `uncertain_pairs` | 证据不足以确认转载关系的发布对 | 显式列出，两端均按独立处理 | 同左 |

### 关系是带证据的断言，不是布尔标记

转载关系（`LineageRelation`）拥有状态机：`candidate → confirmed / rejected`，已确认关系可被 `retracted`，也可 `reopened` 回到候选。文本相似度只产生 `candidate` 线索；只有署名、原链接、人工比对等额外证据支持后才允许 `confirmed`。**证据不足时关系停留在候选，统计通过 `uncertain_pairs` 暴露这种不确定，而不是静默去重。** 被驳回（`rejected`）的关系不参与任何去重，其下游按独立报道计数。

### 来源身份与使用许可相互独立

`Publication` 同时记录 `source_id` 与 `license`。两篇内容文本相同不代表来源身份相同，也不代表共享使用许可；确认转载关系只影响“是否独立报道”的判断，永不推断下游许可，许可缺失时保留 `unknown`。

### 编辑增补不被转载关系抹掉

`has_editorial_addition` 与 `addition_summary` 记录在发布上。即使底本转载关系被确认，只要该发布包含本地采访或自有解释，该来源仍计入独立报道；关系（它从哪里来）与增补（它新增了什么）同时保留。

### 原文与版本保留供复核

`TextVersion` 保存文本原文与 SHA-256 指纹，`Publication.raw_ref` 指向抓取存档。相似度线索、人工判定理由都作为 `RelationEvidence` 挂在关系上，复核时可以回看每个结论的证据链。

## 更正、删稿与双时间

所有变更都是只追加的 `LineageEvent`，物理上不删除历史：

* **系统时间 `recorded_at`**：断言进入账本的时间，历史报告按它截断重放；
* **业务时间 `valid_on`**：事实在现实世界的生效日期，如发布日、删稿日。

更正（关系 `retracted`）、删稿（发布 `withdrawn`）、人工改判（`confirmed/rejected/reopened`）都写入新事件。于是：

* 当前统计（`state_at()` 不传参数）始终反映最新判断；
* 已发布报告用生成时的截止时间调用 `state_at(as_of)`，可复现当时的计数与不确定项；
* 被撤销的关系保留 `retracted` 状态与全部证据，可追溯“当时为何那样计数、后来为何改判”。

## 模块划分

* `lineage.py`：领域模型（故事、文本版本、发布、关系、证据）与只追加事件账本；
* `lineage_analysis.py`：传播 / 独立报道 / 不确定项统计与报告快照；
* `lineage_io.py`：JSON 夹具加载（仅字段映射，不执行夹具内容）；
* `records.py` / `analysis.py` / `report.py`：原有按周期汇总的观测口径，保持不变。
